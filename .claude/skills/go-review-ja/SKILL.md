# Go コードレビュー（日本語）

Goのコードに対して日本語でレビュー依頼を受けたときに、一貫した観点・フォーマットで指摘をまとめるためのスキル。

## レビュー対象の特定

1. デフォルトは `git status` / `git diff` で見える **working tree の未コミット変更**（ステージ済み・未ステージ両方、追跡外ファイルを含む）のうち `.go` ファイルおよび `migration/` 配下の `.sql` ファイル。
2. 「PRを見て」「ブランチ全体をレビューして」のように明示された場合は、対象を現在のブランチと `main` との差分（`git diff main...HEAD`）まで広げる。
3. ユーザーが特定のファイル・関数・「この処理」のように対象を名指しした場合は、それを最優先する。差分の有無に関わらずそのファイルを読んで確認する。
4. 対象になる Go / マイグレーションの変更が見当たらない場合は、無理に指摘を作らず「レビュー対象の差分が見つからない」旨を伝えて終了する。

## レビューの観点

以下の4つの観点で確認する。該当しない観点があれば指摘ゼロで構わない — 観点を埋めるためだけの無理な指摘は追加しないこと。

1. **バグ・正確性** — ロジックの誤り、nilチェック漏れ、境界条件（off-by-one、空スライス等）、goroutine/並行処理のレース、エラーの握りつぶし（`_ = err` や無視されたreturn値）など
2. **Goのイディオム・慣習** — error処理の流儀（早期return、`fmt.Errorf("...: %w", err)` によるwrapping）、命名規則、パッケージ構成、インターフェースの粒度、不要なポインタ/値渡しの選択など
3. **パフォーマンス・効率性** — 不要なアロケーション、ループ内でのDBアクセス（N+1クエリ）、不要なコピーや文字列結合の非効率な書き方
4. **セキュリティ** — SQLインジェクション（`fmt.Sprintf` 等での生SQL組み立て）、入力値検証の欠落、パスワードやトークンなど機密情報のログ出力・ハードコード

このリポジトリは `repository/` 層でSQLを直接組み立てる箇所があるため、セキュリティ観点では特にSQL文字列の組み立て方に注意する。

## マイグレーションファイル（migration/*.sql）のレビュー観点

`.go` の4観点に加えて、マイグレーションは以下を確認する。該当しなければ無理に指摘を作らない。

- **up/downの対応** — `.down.sql` が `.up.sql` の変更を過不足なく取り消せるか（テーブル・カラム名の対応漏れ、DROPし忘れ等）
- **破壊的変更の安全性** — `DROP TABLE` / `DROP COLUMN` / 既存カラムの型変更など、ロールバック不能またはデータ消失を伴う変更が意図通りか
- **既存データへの影響** — デフォルト値のない `NOT NULL` 制約の追加、既存行がある状態での一意制約・外部キー追加など、適用時に失敗しうる変更
- **ロック・パフォーマンス** — 大きなテーブルへのインデックス追加や型変更が本番でロング・ロックを引き起こしうるか
- **命名・ペアリング** — up/downのファイル名（タイムスタンプ）が一致しているか、片方だけ存在していないか

## 指摘の書き方

「読みにくい」「よくない」のような曖昧な指摘は避け、**何を入力・状況にすると何が起きるか**という具体的な失敗シナリオを書く。自信のない指摘は「〜の可能性がある」のように断定を避けた表現にする。差分に含まれないコードへの言及は、直接関係する場合（呼び出し元の契約が変わる等）を除いて避ける。

## 出力フォーマット

このテキスト形式で、必ず日本語で出力する（ReportFindings等の構造化ツールは使わない）。指摘がない重大度の見出しは省略してよい。

```
## レビュー結果

### 🔴 重大
- **ファイル名:行番号** — 一言要約
  - 何が起きるか: 具体的な失敗シナリオ
  - 提案: 直し方の方向性（全面書き直しではなく要点のみ）

### 🟡 警告
- **ファイル名:行番号** — 一言要約
  - 何が起きるか: ...
  - 提案: ...

### 🟢 軽微
- **ファイル名:行番号** — 一言要約
  - 何が起きるか: ...
  - 提案: ...
```

指摘が一件もない場合は、見出しは出さずに「確認した範囲では問題は見つかりませんでした」と一言で伝える。良い点に触れるのは構わないが、レビューの主目的は問題の指摘なので長々と褒めない。
